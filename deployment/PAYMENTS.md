# Резерв и сверка платежей

stock_quantity теперь означает свободный остаток: при checkout он атомарно уменьшается,
при подтверждённой отмене увеличивается обратно. Оплата не списывает уже зарезервированное второй раз.
В админке поле подписано «Доступно к продаже (без резерва)».
Не прибавляйте активные резервы к свободному остатку при ручном редактировании склада.

Заказ хранит неизменные цены/названия, доставку, JSON-запрос и ключ идемпотентности платежа.
Повторное оформление с тем же Idempotency-Key возвращает исходный заказ; изменённые данные
под этим ключом отклоняются. Другой pending-заказ с резервом того же пользователя нужно сначала завершить.
Адрес, телефон и receipt JSON не сохраняются в browser storage и не пишутся в платёжные журналы приложения.
В browser storage сохраняются хеш состава, UUID попытки и email владельца текущей сессии; при выходе они очищаются.

При timeout заказ и резерв сохраняются, в ответе есть order_id. Пользователь может проверить
или продолжить тот же заказ через POST /api/orders/{id}/payment/.
Сверка сравнивает сумму, RUB, order_id, source/checkout_key новых заказов и идентификатор платежа.
POST создания повторяется только с исходными данными/ключом и менее 23 часов от начала операции.
После этого выполняется поиск по списку платежей, без нового создания: гарантия идемпотентности
ЮKassa действует 24 часа. Если платёж не удалось однозначно найти, заказ отмечается для ручной
сверки, резерв не снимается. Сетевые вызовы имеют socket timeout и выполняются вне транзакции БД.

Не снимайте резерв по собственному таймеру: pending-платёж ещё может быть оплачен.
Освобождение происходит после подтверждённого canceled у ЮKassa, включая expired_on_confirmation.
Старые заказы сверяются по payment_id, либо ищутся по metadata и дате; неизвестный старый запрос
никогда не создаётся заново. При нехватке по старому ещё оплачиваемому заказу нужна ручная сверка.

## Запуск

python manage.py reconcile_payments --limit 50

На VDS установить deployment/fishkids-payments.service и .timer в /etc/systemd/system/,
затем systemctl daemon-reload и systemctl enable --now fishkids-payments.timer.
Команда запускается каждые 5 минут и не пересекается с деплоем и сама с собой (общий flock).
Перед первой активацией checkout сверить старые pending-заказы и проверить флаг payment_review_required.
Общие резервные копии и возвраты/двухстадийное списание не входят в этот этап.
